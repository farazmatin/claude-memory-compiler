# Testing

Two layers, both gating CI. They catch different things, and the split is
deliberate.

```bash
uv run pytest                 # 187 tests
uv run pytest -m "not e2e"    # 165 unit, <1s
uv run pytest -m e2e          # 22 functional, ~20s (needs ffmpeg)
```

---

## Layer 1 — unit (165 tests)

Functions in isolation. No network, no subprocesses, no model calls. Fast enough to
run on every save.

| File | Covers |
|---|---|
| `test_ingest.py` | Filename parsing, content-hash dedup, seen-file skipping |
| `test_db.py` | Status ladder, migrations, prior-context windowing, staleness |
| `test_index.py` | Document identity, replace-on-reindex, delete-before-insert |
| `test_compile_minutes.py` | Prompt assembly, size guard, map-reduce, prior context |
| `test_speakers.py` | Candidate derivation, LLM parsing, override cascade |
| `test_entities.py` | Entity/relation parsing, canonicalization, rendering |
| `test_people.py` | Alias resolution, merging, history rewriting |
| `test_backup.py` | SQLite online snapshot, incremental sync |
| `test_answer.py` | Retrieval/synthesis split, alerting |
| `test_doctor.py` | Each preflight check's verdict |
| `test_llm.py` | Provider chain fallthrough, subprocess handling |

Regression tests name the failure they prevent in their docstring, so the reasoning
survives a refactor that moves the code.

## Layer 2 — functional (22 tests)

`test_e2e.py` drives the **real CLI** over a throwaway tree and asserts on
observable outcomes: files on disk, statuses in the manifest, documents in the
index, text on stdout, process exit codes.

Real in these tests:

- the CLI, its argument parsing, and stage orchestration
- real audio generated by ffmpeg, hashed and probed for real
- ffmpeg normalization to 16 kHz mono
- the SQLite manifest and every state transition
- HTTP over a real socket to a LightRAG-shaped server
- **the LLM provider subprocess**: an actual executable, invoked through the real
  `CLIProvider`, receiving the prompt on stdin

Substituted, and only because each needs a GPU, a subscription, or a docker stack:

| Faked | Why | What still gets tested |
|---|---|---|
| ASR model | needs a GPU to be quick | The `Backend` protocol seam — this is also proof the escape hatch works |
| LLM | needs a subscription | Everything except the model's judgement: subprocess, stdin, exit codes, output parsing |
| LightRAG internals | needs docker + Postgres | Every HTTP call the pipeline makes, including the delete-endpoint fallback |

### What the functional layer covers

| Group | Tests |
|---|---|
| Happy path | audio → transcript → minutes → index → answer, with every artifact checked |
| Dedup | byte-identical duplicates ingest once and transcribe once |
| Resumability | stages advance one at a time; a completed batch re-runs as a no-op |
| Recompilation | template bump rebuilds without re-transcribing, old index entry replaced |
| Failure handling | exit codes, alerting, requeue-and-recover, one bad file not stopping the batch |
| Data safety | inbox never modified, backup round-trips into a queryable database |
| Cross-meeting | oldest-first ordering, prior context reaching the compiler, name normalization |
| Operator surface | `status`, `doctor`, `entities`, `graph-sync`, `query --timing` |

## Why the second layer exists

It found two bugs the unit suite could not, and both had passing unit tests
alongside them.

### The batch reported success after total failure

`_run_all` passed `keep_going=True` to the transcribe stage, and `cmd_transcribe`
returns 0 when that flag is set — even if every meeting failed. So a nightly cron
would exit 0 after transcribing nothing, and no alert would fire.

This is the exact defect the review's B1 finding was meant to fix, reintroduced
through a flag. Unit tests could not see it: `cmd_transcribe` was correct in
isolation, `_run_all` was correct in isolation, and the bug lived only in the
argument one passed the other.

The flag conflated two separate things. *Continuing past a bad file* is what the
per-meeting `try/except` does, unconditionally. *Reporting success anyway* is an
interactive convenience that has no business inside an unattended batch.

### The timing line never named the provider

`answer.py` did `from pipeline.llm import last_provider`, which binds the **value**
at import time — `None`, forever. Every `--timing` line read `via None`.

The unit test asserted on `answer.last_provider` after patching that same stale
name, so it passed while the feature was broken. That is a good illustration of a
test that mirrors the implementation instead of checking the behaviour. The
functional replacement asserts `"via gemini"` appears in real CLI output, which
cannot pass unless the whole path works.

## Adding tests

**Prefer functional when the risk is in the wiring** — how stages hand off, what
the CLI passes where, whether a flag means what the caller thinks. That is where
both of the above bugs lived.

**Prefer unit when the risk is in a decision** — regex edge cases, ordering rules,
parsing tolerance, error classification. Functional tests are too slow and too
indirect to enumerate those.

For a new functional test, `tests/e2e_harness.py` provides `FakeLightRAG`,
`FakeASRBackend`, `install_fake_llm()`, `make_audio()` and `apply_env()`.

One trap worth knowing: every module does `from pipeline.config import AUDIO_DIR`,
binding its own copy at import time. Setting the environment alone changes nothing
for an already-imported module, so `apply_env()` patches every module that holds a
copy. It enumerates them deliberately rather than taking a list from the caller —
forgetting one silently points a single stage at the real repo directories, which
is a genuinely confusing failure and exactly what happened the first time these
tests ran.

## Not covered

The functional layer proves the app's own wiring. It cannot prove:

- **Transcription accuracy** — needs real Whisper on real meeting audio.
- **Diarization quality** — needs real pyannote and real overlapping speech.
- **Graph and retrieval quality** — needs real LightRAG/Postgres and a corpus large
  enough to measure deterministic traversal recall.
- **The real CLI invocations** — Codex, Claude, and Antigravity remain
  environment-overridable because their CLI envelopes can change.

`pipeline doctor` checks that these components are present and configured. Only
running one real meeting and reading the result tells you they work well.
